# 暑期红色网站目录恢复与 subtree 发布设计

## 1. 目标

将当前位于 `AiPlace/暑期红色网站/` 的已维护版本恢复到父仓库原有的 `AiPlace/暑期网站/` 路径，在不纳入其他项目改动的前提下保留父仓库历史；验收通过后，通过既有 subtree 方式把 `暑期网站/` 导出为独立仓库根目录，并推送到 `PengjinHao-cell/red-footprint-website` 的 `main` 分支。

本次 Git 推送不等于 CloudBase 部署授权。推送后仅检查 GitHub Actions 和 CloudBase 是否自动产生新构建版本；若未自动触发，手动部署必须再次取得用户明确确认。

## 2. 当前状态与问题

- 父仓库根目录是 `AiPlace/`，当前分支为 `main`。
- Git 历史原本跟踪 `暑期网站/`，但该路径当前在工作区显示为删除。
- 实际维护后的完整项目位于 `暑期红色网站/`，其中一部分文件已被近期提交记录，另一部分仍依赖父仓库旧路径历史。
- 父仓库还包含其他项目及其未提交改动，不能使用无范围限制的暂存或推送方式。
- GitHub 独立网站仓库要求项目文件直接位于仓库根目录，不能把 `AiPlace/` 或 `暑期网站/` 目录层级一并推送。
- 本地发布核对门禁当前因 17 张新增照片尚未进入对象发布与上传核对记录而失败。

## 3. 采用方案

采用“恢复原目录路径，再从父仓库 subtree 导出”的方案：

1. 生成两个目录与 Git 历史的文件级清单，识别网站代码、文档、发布媒体与应排除的原始素材。
2. 将 `暑期红色网站/` 的维护成果恢复到 `暑期网站/`，使 Git 将可匹配内容识别为修改或恢复，而不是无关项目。
3. 仅暂存 `暑期网站/` 和为恢复路径所必需的 `暑期红色网站/` 删除记录；不得暂存 `quiz-app` 或其他兄弟目录。
4. 先完成目录恢复专项提交，再处理发布核对数据，保证每个提交目的单一、可审计、可回退。
5. 所有本地门禁通过后，使用 `git subtree split --prefix=暑期网站` 生成独立网站提交历史。
6. 在推送前检查 subtree 结果的根目录必须直接包含 `package.json`、`src/`、`content/`、`docs/`，且不得包含父仓库其他目录。
7. 将 subtree 导出结果普通推送到 `PengjinHao-cell/red-footprint-website` 的 `main`，不强制覆盖远程历史。

## 4. 文件与媒体边界

网站仓库纳入：

- React/Vite 源码、测试、构建配置和锁文件；
- 页面实际引用的优化后照片、视频封面及必要静态资源；
- 内容清单、来源记录、核对记录和维护文档；
- GitHub Actions 工作流。

默认排除：

- `node_modules/`、`dist/`、测试截图及临时输出；
- CloudBase 密钥、临时凭证和本地环境秘密；
- 未被网站引用的原始大体积视频与原始采集素材；
- 父仓库中的其他项目和无关改动。

17 张新增照片若已经存在于网站发布资源目录，则补齐本地对象发布清单与上传核对状态。任何把文件真正上传到 CloudBase 的操作仍需单独授权；不得把“本地清单完整”伪装成“云端已上传”。

## 5. 验收与错误处理

本地提交和 subtree 推送前必须依次通过：

- 单元测试；
- 代码规范检查；
- 正式构建；
- 内容、地图资源和媒体检查；
- 浏览器端到端测试；
- 完整发布门禁。

如果完整发布门禁要求云端对象已经存在，而本次尚未获得上传授权，则停止在该门禁，不推送、不伪造核对结果，并向用户报告缺失对象与下一项所需授权。

目录恢复后若出现网站之外的暂存内容，立即取消本次暂存并重新按显式路径选择。subtree 导出结果若缺少项目根文件、夹带父仓库目录或与远程历史无法普通快进，则停止推送并报告，不使用强制推送。

## 6. 推送后流程

1. 等待 GitHub Actions 完成，并核对所有检查为绿色。
2. 只读检查 CloudBase `footprint` 服务是否产生对应提交的新构建版本。
3. 如果自动构建已产生，只报告构建状态，不执行额外部署。
4. 如果没有自动触发，报告现状并请求用户单独批准手动进入 `footprint → 更新服务 → 部署`；获批后保持原配置不变启动一次。
5. 构建或部署失败不得覆盖、删除或回滚当前成功版本；任何云端写入或回滚都需要单独授权。

## 7. 完成标准

- 父仓库只包含网站目录相关的新提交，其他项目状态保持不变；
- 本地开发路径恢复为 `AiPlace/暑期网站/`；
- subtree 导出仓库根目录结构正确；
- 本地全部获授权门禁通过；
- 独立网站仓库 `main` 收到普通推送且 GitHub Actions 通过；
- CloudBase 自动构建状态得到核对；需要手动部署时已停在授权点。
