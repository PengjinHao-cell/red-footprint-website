# 开屏低高度桌面适配设计

## 背景

第二轮验收确认：当前开屏在 1440×900 下入口按钮底部略超出视口，在 1366×768 和 1280×720 下入口按钮完全落在首屏之外。主标题、路线动画和按钮的顺序正确，但页面叠加了较大的外层上下内边距、内容顶部留白和约 257px 高的路线动画，整体高度超过常见笔记本视口。

## 目标

- 保留“副标题 → 主标题 → 导语 → 五星四线动画 → 开启寻访”的既定顺序。
- 1280×720、1366×768、1440×900 桌面视口中，副标题、主标题、导语、完整路线动画和入口按钮都在首屏内。
- 主标题不得截断，视觉中心保持在视口高度约 43%–48%。
- 入口按钮继续保持至少 48px 高，不通过缩小触控目标换取空间。
- 390×844 手机布局和高度充足的桌面布局保持现有观感。
- 更正第二轮验收记录中的提交清单。

## 方案选择

采用方案 A：按“桌面宽度 + 低视口高度”启用紧凑布局。

不采用整体缩放，因为它会同时缩小文字和按钮，并可能造成字体发虚；不采用滚动提示，因为主要入口仍会落在首屏之外。

## 布局设计

在现有样式之后增加仅面向低高度桌面的媒体查询：

- 宽度下限使用 `48rem`，避免影响手机和平板窄屏规则；
- 高度上限使用 `56.25rem`（900px），覆盖 1280×720、1366×768 和 1440×900；
- 将 `.welcome-screen` 的纵向内边距限制为 `clamp(1rem, 3svh, 2rem)`，横向内边距保持现有规则；
- 将 `.welcome-screen__content` 的顶部留白限制为 `clamp(5.5rem, 15.5svh, 8.75rem)`；
- 将路线动画宽度限制为 `min(44vw, 15rem)`，并把导语、路线和按钮之间的单项外边距控制为 `0.75rem`；
- 不改变标题字号、标题文案、按钮高度、触控尺寸、色彩和动画语义。

高度超过 900px 的桌面不应用上述紧凑规则。若初始数值未同时满足首屏边界和标题中心阈值，只允许在上述三个纵向空间参数内调整，不改变组件结构或字号。

## 测试设计

先在 Playwright 中增加一个真实布局回归测试，并在修改 CSS 前确认测试失败：

1. 使用桌面 Chromium 加载欢迎页；
2. 依次设置 1280×720、1366×768、1440×900；
3. 检查副标题、主标题、导语、路线和入口按钮的边界均在视口内；
4. 检查主标题中心位于视口高度的 43%–48%；
5. 检查入口按钮高度不小于 48px；
6. 使用 390×844 复核手机布局仍完整，且没有水平溢出。

CSS 修改后重复该目标测试得到 GREEN，再运行完整 E2E、发布门禁和真实浏览器视觉测量。
