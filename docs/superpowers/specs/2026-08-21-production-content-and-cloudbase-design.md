# 红色足迹 09B：三维地图、生产内容与 CloudBase 静态交付设计

日期：2026-08-21

状态：用户已确认修订路线

目标环境：`red-footprint-preview-d5322636bd`

## 1. 目标

09B 把现有原型整理成可部署的纯静态网站：保留三维地球、红心点位和镜头飞行动画；以项目已下载的官方平面标准地图作为中国疆域视觉依据，生成适合球面渲染的地图数据；整理八馆正式内容与媒体；上传静态媒体到 CloudBase 云存储；由 CloudBase 静态托管构建并发布网站。

用户已明确决定：项目不再设置地图审图、签字或送审材料门禁。地图只做项目内部的技术与视觉核验，不再因 `mapCompliance.status` 阻断内容开发、构建或部署。页面仍保留地图来源与原图审图号说明，但不描述成三维衍生形态获得了新的审图批准。

## 2. 不可变边界

- React/Vite 纯静态单页应用，不使用数据库、云函数、云托管容器、认证或运行时内容 API。
- CloudBase 静态托管承载 `dist/`，CloudBase 云存储/CDN 承载图片、视频、封面和 VTT。
- 原始图片、视频、DOC/DOCX、XLSX 和地图材料保持只读，不提交大媒体。
- 不把测试 fixture、占位 URL、未核实事实或本机路径写入生产数据。
- 不使用子代理；每个 Task 独立本地提交，不 amend、不 push。
- 上传、权限修改、GitHub 绑定和部署仍分别需要用户明确授权。
- 取消地图审图门禁不等于宣称三维地图获得监管审核；这是项目方接受的发布风险。

## 3. 三维地图设计

### 3.1 数据来源

视觉依据固定为：

- `docs/compliance/maps/china-map-gs-2023-2762-original.jpg`
- 审图号：`GS(2023)2762号`
- 来源：自然资源部标准地图服务系统下载材料
- 原始 ZIP、JPG 和规范 PDF 的既有 SHA-256 继续保留作来源记录

原 JPG 不是等经纬度球面纹理，禁止把整张带标题、图例和空白边框的图片直接包裹到球体。实现采用“平面图作为人工校准基准，球面矢量/纹理作为运行资源”：生成或整理 Globe.gl/Three.js 可用的中国疆域数据，并对照原图检查大陆轮廓、国界、行政边界和主要岛屿。

### 3.2 渲染与交互

- 保留完整球体、旋转、缩放和中国区域视角。
- 中国疆域在明亮米白/砂岩风格中清晰可辨，不使用黑色太空背景。
- 八个红心使用既有 GCJ-02 坐标；一大红心仍位于兴业路76号，页面参观地址为黄陂南路374号。
- 点击红心执行现有相机飞行并打开同一详情面板。
- WebGL 初始化失败时继续提供八馆原生按钮列表。
- reduced-motion 继续使用淡入淡出，不执行空间飞行。

### 3.3 地图检查

`check:map` 从审批材料门禁改为项目内部地图资源完整性检查，只验证：

- 地图来源记录、原图审图号和摘要存在；
- 运行时地图资源存在、格式合法、摘要匹配；
- 八个点位数量、ID、坐标范围和唯一性正确；
- 人工视觉检查覆盖大陆轮廓、国界、行政边界、岛屿和八个红心；
- 3D 初始化失败时可访问降级列表仍有效。

不再要求最终三维形态的新审图号、地图负责人签字或 `publicUseAllowed` 审批字段。`npm run check:map` 必须能在本地和 CI 中通过，不能保留硬编码 blocked，也不能通过删除检查脚本来通过。

## 4. 内容与生产数据

八馆稳定 ID、GCJ-02 坐标和正式名称沿用现有设计。内容来源以本地 DOC/DOCX 为线索，以场馆官网、地方政府、文旅部门等权威页面补足正式名称、地址、开放时间、预约方式、参观提示、历史事件、人物身份、年代和展品含义。

每馆生产内容包括基础信息、历史印记、人物故事、精神传承、寻访感悟及对应事实来源链接和访问日期。团队感悟与事实陈述分开，时效信息在发布前再次核对。生成的 `src/data/sites.json` 恰好八条，不引用测试 fixture，不包含占位域名。

## 6. CloudBase 交付

Task 1 已完成只读环境盘点，确认环境位于 `ap-shanghai`，静态托管和云存储存在；尚未读取的 GitHub 绑定与权限字段保持 unknown，不通过猜测补值。

媒体上传前，用户需确认环境、对象数量、总大小和目标前缀。上传只新增版本对象，不覆盖、不删除、不放宽权限。上传后通过只读清单与本地 manifest 对账，再把真实 HTTPS/CDN URL 写入生产数据。

GitHub 绑定与首次部署分别请求授权。构建参数为 `main`、`npm ci`、`npm run verify:release`、输出 `dist`、部署路径 `/`。`verify:release` 顺序执行内容、地图技术检查、lint、单测、构建和必要 E2E；全部通过才部署。
